1. zlib とは何か

1.1 データ圧縮の世界へようこそ

私たちが日常的に扱うデータ――テキストファイル、画像、ウェブページ――の多くには冗長性があります。同じパターンが何度も繰り返されていたり、使われていない情報が含まれていたりします。データ圧縮とは、この冗長性を取り除いてデータのサイズを小さくする技術です。

圧縮技術は、大きく2つに分類されます。

種類 特徴 用途の例
可逆圧縮（lossless） 完全に元のデータに戻せる テキスト、プログラム、PNG
非可逆圧縮（lossy） 一部の情報が失われる JPEG、MP3、動画

zlib は可逆圧縮ライブラリです。圧縮したデータを展開すると、1ビットの狂いもなく元のデータが復元されます。

1.2 zlib の概要

zlib は、Jean-loup Gailly と Mark Adler によって開発された、フリーの汎用データ圧縮ライブラリです。1995年に最初のバージョンがリリースされて以来、世界中で最も広く使われている圧縮ライブラリの一つとなっています。

graph LR A[元のデータ] -->|圧縮| B[zlib] B -->|圧縮データ| C[小さなデータ] C -->|展開| D[zlib] D -->|元のデータ| E[復元されたデータ] style B fill:#4CAF50,color:#fff style D fill:#2196F3,color:#fff

zlib の主な特徴は次のとおりです。

  • 高い互換性: C言語で書かれており、ほぼすべてのプラットフォームで動作する
  • オープンソース: 非常に寛容なライセンス（zlib ライセンス）で自由に利用可能
  • 高い信頼性: 30年近い実績があり、枯れた技術として安定している
  • 標準的な圧縮形式: Deflate、gzip、zlib の各フォーマットをサポート
  • ストリーム処理: データを少しずつ処理できるため、メモリ使用量を抑えられる

1.3 zlib が使われている場所

zlib は驚くほど多くの場所で使われています。あなたがこの本を読んでいる今この瞬間も、zlib が動いている可能性が高いでしょう。

1.3.1 ウェブ

HTTP の Content-Encoding: gzip や Content-Encoding: deflate による通信圧縮は、zlib をベースにしています。ウェブブラウザとウェブサーバーの間でやり取りされるデータの多くは、zlib によって圧縮・展開されています。

1.3.2 ファイル形式

多くのファイル形式が内部で zlib を使っています。

  • PNG 画像: 画像データの圧縮に Deflate を使用
  • ZIP アーカイブ: 個々のファイルの圧縮に Deflate を使用
  • gzip ファイル: Unix/Linux で標準的な圧縮形式
  • PDF: ストリームデータの圧縮に使用

1.3.3 データベースとストレージ

  • Git: オブジェクトストレージの圧縮
  • SQLite: オプションの圧縮拡張
  • 各種データベース: データページの圧縮

1.3.4 プログラミング言語

ほぼすべての主要なプログラミング言語が、標準ライブラリまたは広く使われるパッケージとして zlib バインディングを提供しています。

  • Python: zlib モジュール（標準ライブラリ）
  • Ruby: Zlib モジュール（標準ライブラリ）
  • Java: java.util.zip パッケージ
  • Node.js: zlib モジュール
  • Go: compress/flate, compress/gzip, compress/zlib パッケージ

1.4 zlib の歴史

zlib の歴史を理解することは、その設計思想を理解する上で重要です。

1.4.1 誕生の背景

1990年代初頭、Phil Katz が開発した PKZIP とその圧縮アルゴリズム Deflate は広く普及していましたが、特許の問題がありました。Info-ZIP プロジェクトがフリーの実装を提供しようとしていましたが、汎用ライブラリとしては設計されていませんでした。

Jean-loup Gailly（圧縮部分）と Mark Adler（展開部分）は、誰でも自由に使える汎用圧縮ライブラリとして zlib を設計・実装しました。

1.5 zlib ライセンス

zlib ライセンスは非常に寛容なオープンソースライセンスです。商用利用を含め、ほぼ制限なく使用できます。

主な条件は以下の3つだけです。

  1. 改変したソースを配布する場合は、改変した旨を明記すること
  2. ソフトウェアの出自を偽って表示しないこと
  3. ライセンス通知をソース配布から削除しないこと

Note

zlib ライセンスはバイナリ配布時にライセンス表記を求めないため、組み込みシステムやゲームなど、表示領域が限られる環境でも採用しやすいのが特徴です。

    printf("圧縮後サイズ: %lu バイト\n", compressed_len);

    /* 展開 */
    ret = uncompress(decompressed, &decompressed_len,
                     compressed, compressed_len);
    if (ret != Z_OK) {
        fprintf(stderr, "展開に失敗しました: %d\n", ret);
        free(compressed);
        free(decompressed);
        return 1;
    }

    /* 検証 */
    if (strcmp(original, (const char *)decompressed) == 0) {
        printf("検証成功: 元のデータと一致しました\n");
    } else {
        printf("検証失敗: データが一致しません\n");
    }

    free(compressed);
    free(decompressed);
    return 0;
}

3. 基本概念

3.1 はじめに

zlib の API を効果的に使うためには、いくつかの基本概念を理解しておく必要があります。この章では、圧縮の仕組みからデータ形式、ストリーム処理の考え方まで、zlib を使う上で欠かせない知識を解説します。

3.2 圧縮アルゴリズムの基礎

3.2.1 LZ77 アルゴリズム

zlib が使用する Deflate アルゴリズムは、LZ77 とハフマン符号化の組み合わせです。まず LZ77 の考え方を見てみましょう。

LZ77 は「スライディングウィンドウ」方式の辞書ベース圧縮です。過去に出現したデータパターンへの参照（距離と長さのペア）に置き換えることで圧縮します。

元のデータ: ABCABCABCABC

この場合、最初の ABC の後、同じパターンが繰り返されています。LZ77 はこれを次のように表現します。

ABC（3文字前に戻って3文字コピー）（3文字前に戻って3文字コピー）（3文字前に戻って3文字コピー）
graph LR subgraph 元データ A1["A B C A B C A B C A B C"] end subgraph 圧縮後 B1["A B C"] --> B2["(3,3)"] --> B3["(3,3)"] --> B4["(3,3)"] end

3.2.2 ハフマン符号化

ハフマン符号化は、出現頻度の高いシンボルに短いビット列を、頻度の低いシンボルに長いビット列を割り当てる方式です。

たとえば、テキスト中で e が最も多く出現し、z がほとんど出現しない場合:

文字 出現頻度 固定長コード ハフマンコード
e 高い 8ビット 2ビット
t やや高い 8ビット 3ビット
z 低い 8ビット 9ビット

頻出文字のビット数が減るため、全体としてデータが小さくなります。

3.2.3 Deflate = LZ77 + ハフマン符号化

Deflate アルゴリズムは、この2つの手法を組み合わせています。

graph TD A[入力データ] --> B[LZ77
重複パターンの検出・置換] B --> C[ハフマン符号化
頻度ベースの可変長符号化] C --> D[圧縮データ] style B fill:#4CAF50,color:#fff style C fill:#2196F3,color:#fff
  1. まず LZ77 で重複するパターンを検出し、参照に置き換える
  2. 次にハフマン符号化で、結果をさらに効率的なビット表現にする

3.3 3つのデータ形式

zlib は3つの異なるデータ形式をサポートしています。それぞれの違いを理解することが重要です。

3.3.1 raw deflate

Deflate アルゴリズムで圧縮されたデータそのものです。ヘッダやチェックサムを含みません。

[圧縮データ]
  • ヘッダ: なし
  • チェックサム: なし
  • 用途: ZIP ファイル内部、PNG 内部など、外側のコンテナがエラーチェックを提供する場合

3.3.2 zlib 形式

zlib 形式は、Deflate データに軽量なヘッダとチェックサムを追加した形式です（RFC 1950）。

[CMF(1バイト)][FLG(1バイト)][圧縮データ][Adler-32(4バイト)]
  • ヘッダ: 2バイト（圧縮方式とウィンドウサイズ）
  • チェックサム: Adler-32（4バイト）
  • 用途: ネットワーク通信、compress()/uncompress() のデフォルト

3.3.3 gzip 形式

gzip 形式は、ファイルの圧縮用に設計された形式です（RFC 1952）。

[ID1][ID2][CM][FLG][MTIME(4)][XFL][OS][...オプション...][圧縮データ][CRC-32(4)][ISIZE(4)]
  • ヘッダ: 10バイト以上（ファイル名、タイムスタンプなどのメタデータを含む）
  • チェックサム: CRC-32（4バイト）+ 元データのサイズ（4バイト）
  • 用途: gzip コマンド、HTTP 通信（Content-Encoding: gzip）

3.3.4 形式の比較

特性 raw deflate zlib 形式 gzip 形式
ヘッダ なし 2バイト 10バイト以上
チェックサム なし Adler-32 CRC-32
メタデータ なし なし ファイル名、日時など
RFC 1951 1950 1952
オーバーヘッド 最小 6バイト 18バイト以上

Tip

どの形式を使うべきか迷ったら、以下を基準にしてください。

  • ファイルとして保存するなら gzip 形式
  • ネットワーク通信やメモリ内の一時的な圧縮なら zlib 形式
  • 外側のコンテナがある場合は raw deflate

3.4 ストリーム処理

zlib の最も重要な概念の一つがストリーム処理です。

3.4.1 なぜストリーム処理が必要か

ストリーム処理の中心となるのが z_stream 構造体です。

3.6 チェックサム

zlib は2種類のチェックサムアルゴリズムを提供しています。

3.6.1 Adler-32

Adler-32 は zlib 形式で使用される高速なチェックサムです。

uLong adler = adler32(0L, Z_NULL, 0);        /* 初期化 */
adler = adler32(adler, data, data_len);        /* データの追加 */
adler = adler32(adler, more_data, more_len);   /* さらにデータを追加 */

特徴:

  • 高速: CRC-32 よりも計算が速い
  • 弱い検出能力: CRC-32 に比べるとエラー検出能力は劣る
  • 用途: zlib 形式の完全性チェック

3.6.2 CRC-32

CRC-32 は gzip 形式で使用される標準的なチェックサムです。

uLong crc = crc32(0L, Z_NULL, 0);         /* 初期化 */
crc = crc32(crc, data, data_len);           /* データの追加 */
crc = crc32(crc, more_data, more_len);      /* さらにデータを追加 */

特徴:

  • 信頼性が高い: エラー検出能力が優れている
  • やや遅い: Adler-32 より計算コストが高い
  • 標準的: 多くのファイル形式やプロトコルで採用されている

3.6.3 どちらを使うべきか

高速なデータ検証 Adler-32

ネットワーク通信 CRC-32
zlib 形式との互換性 Adler-32
gzip 形式との互換性 CRC-32

3.7 フラッシュ（flush）の種類

ストリーム処理において、フラッシュは「今のデータをどこまで出力するか」を制御します。

フラッシュモード 定数 説明
フラッシュなし Z_NO_FLUSH zlib に出力タイミングを任せる
部分フラッシュ Z_PARTIAL_FLUSH 内部状態を部分的に出力
同期フラッシュ Z_SYNC_FLUSH ここまでの入力をすべて出力し、バイト境界に合わせる
完全フラッシュ Z_FULL_FLUSH 同期フラッシュ + 辞書をリセット
終了 Z_FINISH 入力の終了を通知し、残りのデータを出力

Note

通常の使用では Z_NO_FLUSH を使い、最後に Z_FINISH を呼び出すだけで十分です。Z_SYNC_FLUSH はリアルタイム通信など、データを即座に送信したい場合に使います。

3.8 メモリ管理

zlib は内部でメモリを動的に確保します。デフォルトでは malloc() と free() を使いますが、z_stream の zalloc と zfree フィールドにカスタムアロケータを設定することも可能です。

z_stream strm;
strm.zalloc = Z_NULL;  /* デフォルトの malloc を使用 */
strm.zfree = Z_NULL;   /* デフォルトの free を使用 */
strm.opaque = Z_NULL;  /* アロケータに渡すコンテキスト */

デフォルト設定（windowBits=15, memLevel=8）の場合、約 256KB のメモリを使用します。

この章では、zlib を使ったデータ圧縮の方法を、簡単な API から高度なストリーム API まで段階的に解説します。

4.2 compress() — 最も簡単な圧縮

zlib が提供する最もシンプルな圧縮関数が compress() です。データ全体をメモリ上で一度に圧縮します。

4.2.1 関数シグネチャ

int compress(Bytef *dest, uLongf *destLen,
             const Bytef *source, uLong sourceLen);
引数 説明
dest 圧縮データの出力先バッファ
destLen 入力時: バッファサイズ、出力時: 実際の圧縮後サイズ
source 圧縮する元データ
sourceLen 元データのサイズ

4.2.2 使用例

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <zlib.h>

int main(void)
{
    const char *source = "This is a test string for compression with zlib. "
                         "Repeated data compresses well. "
                         "Repeated data compresses well. "
                         "Repeated data compresses well.";
    uLong source_len = (uLong)strlen(source) + 1;

    /* 圧縮先バッファのサイズを計算 */
    uLong dest_len = compressBound(source_len);
    Bytef *dest = (Bytef *)malloc(dest_len);
    if (dest == NULL) {
        fprintf(stderr, "メモリ確保に失敗しました\n");
        return 1;
    }

    /* 圧縮実行 */
    int ret = compress(dest, &dest_len, (const Bytef *)source, source_len);
    if (ret != Z_OK) {
        fprintf(stderr, "圧縮エラー: %d\n", ret);
        free(dest);
        return 1;
    }

    printf("元データ:     %lu バイト\n", source_len);
    printf("圧縮データ:   %lu バイト\n", dest_len);

    free(dest);
    return 0;
}

4.2.3 compressBound() — 出力バッファサイズの見積もり

compressBound() は、指定したサイズのデータを圧縮した場合の最大出力サイズを返します。圧縮先バッファの確保に使います。

uLong compressBound(uLong sourceLen);

Note

compressBound() が返すサイズは、最悪ケース（データがまったく圧縮できない場合）を想定した値です。実際の圧縮後サイズはこれよりも小さくなります。

4.2.4 compress2() — 圧縮レベルの指定

圧縮レベルを指定したい場合は compress2() を使います。

int compress2(Bytef *dest, uLongf *destLen,
              const Bytef *source, uLong sourceLen,
              int level);

/* 最速の圧縮 */
ret = compress2(dest, &dest_len, source, source_len, Z_BEST_SPEED);

/* 最高圧縮率 */
ret = compress2(dest, &dest_len, source, source_len, Z_BEST_COMPRESSION);

/* デフォルト（compress() と同じ） */
ret = compress2(dest, &dest_len, source, source_len, Z_DEFAULT_COMPRESSION);

4.3 ストリーム API による圧縮

大きなデータやファイルを圧縮する場合、ストリーム API を使います。データを小さなチャンクに分けて順次処理できるため、メモリ使用量を一定に保てます。

4.3.1 基本的な流れ

graph TD A["1. deflateInit()"] --> B["2. 入力データをセット
next_in, avail_in"] B --> C["3. deflate(Z_NO_FLUSH)"] C --> D{出力バッファが一杯?} D -->|はい| E[出力データを書き出し
next_out, avail_out をリセット] E --> C D -->|いいえ| F{入力データが残っている?} F -->|はい| B F -->|いいえ| G["4. deflate(Z_FINISH)"] G --> H{戻り値 == Z_STREAM_END?} H -->|いいえ| I[出力データを書き出し] I --> G H -->|はい| J[残りの出力データを書き出し] J --> K["5. deflateEnd()"]

4.3.2 ファイル圧縮の実装

/* file_compress.c - ファイルのストリーム圧縮 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <zlib.h>

#define CHUNK_SIZE 16384  /* 16KB */

int compress_file(const char *input_path, const char *output_path, int level)
{
    FILE *input = fopen(input_path, "rb");
    if (!input) {
        perror("入力ファイルを開けません");
        return -1;
    }

    FILE *output = fopen(output_path, "wb");
    if (!output) {
        perror("出力ファイルを開けません");
        fclose(input);
        return -1;
    }

    /* ストリームの初期化 */
    z_stream strm;
    memset(&strm, 0, sizeof(strm));

    int ret = deflateInit(&strm, level);
    if (ret != Z_OK) {
        fprintf(stderr, "deflateInit 失敗: %d\n", ret);
        fclose(input);
        fclose(output);
        return ret;
    }

    /* 入出力バッファ */
    unsigned char in_buf[CHUNK_SIZE];
    unsigned char out_buf[CHUNK_SIZE];
    int flush;

    /* メインループ */
    do {
        /* 入力データを読み込む */
        strm.avail_in = fread(in_buf, 1, CHUNK_SIZE, input);
        if (ferror(input)) {
            deflateEnd(&strm);
            fclose(input);
            fclose(output);
            return Z_ERRNO;
        }
        flush = feof(input) ? Z_FINISH : Z_NO_FLUSH;
        strm.next_in = in_buf;

        /* 入力チャンクを圧縮する（出力バッファが一杯になるたびにループ） */
        do {
            strm.avail_out = CHUNK_SIZE;
            strm.next_out = out_buf;

            ret = deflate(&strm, flush);
            if (ret == Z_STREAM_ERROR) {
                deflateEnd(&strm);
                fclose(input);
                fclose(output);
                return ret;
            }

            /* 出力バッファに書き込まれたデータをファイルに出力 */
            unsigned have = CHUNK_SIZE - strm.avail_out;
            if (fwrite(out_buf, 1, have, output) != have || ferror(output)) {
                deflateEnd(&strm);
                fclose(input);
                fclose(output);
                return Z_ERRNO;
            }
        } while (strm.avail_out == 0);
        /* avail_out > 0 なら、この入力チャンクの処理は完了 */

    } while (flush != Z_FINISH);
    /* ret が Z_STREAM_END であることを確認 */

    printf("圧縮完了: %lu → %lu バイト (%.1f%%)\n",
           strm.total_in, strm.total_out,
           (1.0 - (double)strm.total_out / strm.total_in) * 100);

    /* 後処理 */
    deflateEnd(&strm);
    fclose(input);
    fclose(output);

    return Z_OK;
}

int main(int argc, char *argv[])
{
    if (argc < 3) {
        fprintf(stderr, "使い方: %s <入力ファイル> <出力ファイル> [圧縮レベル]\n",
                argv[0]);
        return 1;
    }

    int level = Z_DEFAULT_COMPRESSION;
    if (argc >= 4) {
        level = atoi(argv[3]);
        if (level < 0 || level > 9) {
            fprintf(stderr, "圧縮レベルは 0〜9 を指定してください\n");
            return 1;
        }
    }

    return compress_file(argv[1], argv[2], level);
}

4.4 deflateInit2() — 詳細な初期化

deflateInit() の拡張版である deflateInit2() を使うと、より細かい制御が可能です。

int deflateInit2(z_streamp strm,
                 int level,        /* 圧縮レベル (0-9) */
                 int method,       /* 圧縮方式 (Z_DEFLATED のみ) */
                 int windowBits,   /* ウィンドウサイズ */
                 int memLevel,     /* メモリ使用量 (1-9) */
                 int strategy);    /* 圧縮戦略 */

4.4.1 windowBits の意味

windowBits パラメータは、データ形式とウィンドウサイズの両方を制御します。

windowBits の範囲 形式 ウィンドウサイズ
8〜15 zlib 形式 2^windowBits バイト
-8〜-15 raw deflate 2^abs(windowBits) バイト
24〜31 (16+8〜16+15) gzip 形式 2^(windowBits-16) バイト 
/* zlib 形式（デフォルト） */
deflateInit2(&strm, level, Z_DEFLATED, 15, 8, Z_DEFAULT_STRATEGY);

/* raw deflate */
deflateInit2(&strm, level, Z_DEFLATED, -15, 8, Z_DEFAULT_STRATEGY);

/* gzip 形式 */
deflateInit2(&strm, level, Z_DEFLATED, 15 + 16, 8, Z_DEFAULT_STRATEGY);

4.4.2 圧縮戦略

圧縮戦略は、データの特性に応じた最適化のヒントを提供します。

戦略 定数 適したデータ
デフォルト Z_DEFAULT_STRATEGY 一般的なデータ
フィルタ Z_FILTERED フィルタで生成されたデータ（差分データなど）
ハフマンのみ Z_HUFFMAN_ONLY ハフマン符号化のみ使用（LZ77 なし）
RLE Z_RLE ランレングス符号化のみ（PNG 画像に最適）
固定 Z_FIXED 固定ハフマンテーブルを使用

Tip

ほとんどの場合、Z_DEFAULT_STRATEGY で十分です。PNG 画像の圧縮など、特定の用途で Z_RLE や Z_FILTERED が効果的なことがあります。

4.5 辞書を使った圧縮

似たようなデータを繰り返し圧縮する場合、事前定義辞書を使うと初期段階の圧縮効率が向上します。

/* 辞書データ（圧縮するデータに含まれそうな文字列パターン） */
const char *dictionary = "HTTP/1.1 Content-Type: application/json "
                         "\"status\":\"success\" \"data\":";
uLong dict_len = (uLong)strlen(dictionary);

/* 圧縮時: 辞書をセット */
z_stream strm;
memset(&strm, 0, sizeof(strm));
deflateInit(&strm, Z_DEFAULT_COMPRESSION);
deflateSetDictionary(&strm, (const Bytef *)dictionary, dict_len);

/* 辞書の Adler-32 を記録（展開時に必要） */
uLong dict_adler = strm.adler;

/* ... 通常の圧縮処理 ... */

展開側では、inflate() が Z_NEED_DICT を返した場合に辞書をセットします。これについては次の章で説明します。

5. 展開の基本

5.1 はじめに

圧縮の反対の操作が展開（decompression）です。この章では、zlib を使ったデータの展開方法を、簡易 API からストリーム API まで解説します。

5.2 uncompress() — 最も簡単な展開

compress() の対になる関数が uncompress() です。

int uncompress(Bytef *dest, uLongf *destLen,
               const Bytef *source, uLong sourceLen);
引数 説明
dest 展開データの出力先バッファ
destLen 入力時: バッファサイズ、出力時: 実際の展開後サイズ
source 圧縮データ
sourceLen 圧縮データのサイズ

5.2.1 使用例

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <zlib.h>

int main(void)
{
    /* まず圧縮する */
    const char *original = "Hello, zlib! Compression and decompression example.";
    uLong original_len = (uLong)strlen(original) + 1;

    uLong compressed_len = compressBound(original_len);
    Bytef *compressed = (Bytef *)malloc(compressed_len);
    compress(compressed, &compressed_len,
             (const Bytef *)original, original_len);

    /* 展開する */
    uLong decompressed_len = original_len;  /* 元のサイズを知っている必要がある */
    Bytef *decompressed = (Bytef *)malloc(decompressed_len);

    int ret = uncompress(decompressed, &decompressed_len,
                         compressed, compressed_len);
    if (ret == Z_OK) {
        printf("展開成功: %s\n", (const char *)decompressed);
    } else {
        fprintf(stderr, "展開失敗: %d\n", ret);
    }

    free(compressed);
    free(decompressed);
    return 0;
}

Warning

uncompress() を使うには、展開後のデータサイズを事前に知っている必要があります。サイズが不明な場合は、バッファを徐々に大きくして再試行するか、ストリーム API を使用してください。

5.2.2 元のサイズが不明な場合

元のサイズがわからない場合のパターンです。

int uncompress_unknown_size(Bytef **dest, uLong *dest_len,
                            const Bytef *source, uLong source_len)
{
    /* 圧縮データの4倍から始めて、失敗したら倍にしていく */
    *dest_len = source_len * 4;
    int ret;

    do {
        *dest = (Bytef *)realloc(*dest, *dest_len);
        if (*dest == NULL) {
            return Z_MEM_ERROR;
        }

        uLong try_len = *dest_len;
        ret = uncompress(*dest, &try_len, source, source_len);

        if (ret == Z_OK) {
            *dest_len = try_len;
            return Z_OK;
        }

        if (ret == Z_BUF_ERROR) {
            *dest_len *= 2;  /* バッファを倍にして再試行 */
        }
    } while (ret == Z_BUF_ERROR);

    return ret;
}

/* file_decompress.c - ファイルのストリーム展開 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <zlib.h>

#define CHUNK_SIZE 16384

int decompress_file(const char *input_path, const char *output_path)
{
    FILE *input = fopen(input_path, "rb");
    if (!input) {
        perror("入力ファイルを開けません");
        return -1;
    }

    FILE *output = fopen(output_path, "wb");
    if (!output) {
        perror("出力ファイルを開けません");
        fclose(input);
        return -1;
    }

    /* ストリームの初期化 */
    z_stream strm;
    memset(&strm, 0, sizeof(strm));

    int ret = inflateInit(&strm);
    if (ret != Z_OK) {
        fprintf(stderr, "inflateInit 失敗: %d\n", ret);
        fclose(input);
        fclose(output);
        return ret;
    }

    unsigned char in_buf[CHUNK_SIZE];
    unsigned char out_buf[CHUNK_SIZE];

    /* メインループ */
    do {
        strm.avail_in = fread(in_buf, 1, CHUNK_SIZE, input);
        if (ferror(input)) {
            inflateEnd(&strm);
            fclose(input);
            fclose(output);
            return Z_ERRNO;
        }
        if (strm.avail_in == 0)
            break;
        strm.next_in = in_buf;

        /* 入力チャンクを展開する */
        do {
            strm.avail_out = CHUNK_SIZE;
            strm.next_out = out_buf;

            ret = inflate(&strm, Z_NO_FLUSH);
            switch (ret) {
            case Z_NEED_DICT:
                ret = Z_DATA_ERROR;  /* 辞書なしの場合はエラーとして扱う */
                /* FALLTHROUGH */
            case Z_DATA_ERROR:
            case Z_MEM_ERROR:
            case Z_STREAM_ERROR:
                inflateEnd(&strm);
                fclose(input);
                fclose(output);
                return ret;
            }

            unsigned have = CHUNK_SIZE - strm.avail_out;
            if (fwrite(out_buf, 1, have, output) != have || ferror(output)) {
                inflateEnd(&strm);
                fclose(input);
                fclose(output);
                return Z_ERRNO;
            }
        } while (strm.avail_out == 0);

    } while (ret != Z_STREAM_END);

    printf("展開完了: %lu → %lu バイト\n", strm.total_in, strm.total_out);

    inflateEnd(&strm);
    fclose(input);
    fclose(output);

    return ret == Z_STREAM_END ? Z_OK : Z_DATA_ERROR;
}

int main(int argc, char *argv[])
{
    if (argc != 3) {
        fprintf(stderr, "使い方: %s <圧縮ファイル> <出力ファイル>\n", argv[0]);
        return 1;
    }

    return decompress_file(argv[1], argv[2]);
}

5.5 inflateInit2() — 詳細な初期化

圧縮時の deflateInit2() に対応するのが inflateInit2() です。

int inflateInit2(z_streamp strm, int windowBits);

windowBits の範囲 形式
8〜15 zlib 形式
-8〜-15 raw deflate
24〜31 (16+8〜16+15) gzip 形式

5.7 inflateSync() — 破損データのリカバリ

データの一部が破損している場合、inflateSync() を使って次の有効なブロック境界まで読み飛ばすことができます。

/* データが壊れている可能性がある場合の展開 */
ret = inflate(&strm, Z_NO_FLUSH);

if (ret == Z_DATA_ERROR) {
    fprintf(stderr, "データ破損を検出。リカバリを試みます...\n");

    ret = inflateSync(&strm);
    if (ret == Z_OK) {
        fprintf(stderr, "次の有効なブロックを発見しました\n");

    } else {

    }
}

Caution

inflateSync() は、Z_FULL_FLUSH または Z_SYNC_FLUSH で作成された同期ポイントを探します。通常の圧縮データ（Z_NO_FLUSH のみ）では、リカバリポイントが存在しない場合があります。

6. gzip ファイルの操作

6.1 はじめに

zlib は、gzip 形式のファイルを簡単に扱うための高レベル API を提供しています。この API は C の標準 I/O（fopen / fread / fwrite）に似たインターフェースを持ち、透過的にデータの圧縮・展開を行います。

6.2 gzip API の概要

gzip API は、通常のファイル操作と同じ感覚で圧縮ファイルを扱えるように設計されています。

6.3 ファイルのオープンとクローズ

6.3.1 gzopen()

gzFile gzopen(const char *path, const char *mode);

mode 文字列は fopen() に似ていますが、圧縮レベルと戦略の指定も可能です。

"rb" 読み込み（展開）用に開く
"wb" 書き込み（圧縮）用に開く（デフォルトレベル 6）

int gzclose(gzFile file);

gzip ファイルを閉じます。書き込みモードの場合、残りのバッファをフラッシュして gzip トレーラを書き込みます。

6.4.2 書き込みの例

#include <string.h>
#include <zlib.h>

    const char *lines[] = {
        "1行目: zlib の gzip API のテストです。\n",

6.4.3 読み込みの例

#include <stdio.h>
#include <zlib.h>

#define BUF_SIZE 1024

int main(void)
{

        return 1;

6.6 シークとポジション

gzip API はランダムアクセスにも対応しています（ただし制限があります）。

/* 現在の位置を取得（展開後のデータ上の位置） */
z_off_t gztell(gzFile file);

/* 位置を移動 */

/* 先頭に巻き戻し */
int gzrewind(gzFile file);

/* EOF の確認 */
int gzeof(gzFile file);

Warning

書き込みモードでの gzseek() は前方シークのみサポートされています。読み込みモードでは前方・後方ともにシークできますが、後方シークは内部でデータを先頭から再展開するため、非常に遅くなる可能性があります。

gzFile gz = gzopen("data.gz", "rb");

/* 100 バイト目にシーク */
gzseek(gz, 100, SEEK_SET);

/* 現在位置から 50 バイト先に移動 */
gzseek(gz, 50, SEEK_CUR);

/* 現在位置を取得 */
z_off_t pos = gztell(gz);
printf("現在位置: %ld\n", (long)pos);

gzclose(gz);

6.7 バッファサイズの設定

gzFile gz = gzopen("large_file.gz", "rb");

6.10 実践例: ログファイルの圧縮保存

ログをリアルタイムで圧縮ファイルに保存する例です。

/* gzip_logger.c */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <zlib.h>

typedef struct {
    gzFile file;
    int count;
} Logger;

Logger *logger_open(const char *path)
{
    Logger *logger = (Logger *)malloc(sizeof(Logger));
    if (!logger) return NULL;

    logger->file = gzopen(path, "wb6");
    if (!logger->file) {
        free(logger);
        return NULL;
    }

    /* バッファサイズを 64KB に設定 */
    gzbuffer(logger->file, 65536);

    logger->count = 0;
    return logger;
}

void logger_write(Logger *logger, const char *level, const char *message)
{
    time_t now = time(NULL);
    struct tm *t = localtime(&now);
    char timestamp[32];
    strftime(timestamp, sizeof(timestamp), "%Y-%m-%d %H:%M:%S", t);

    gzprintf(logger->file, "[%s] [%s] %s\n", timestamp, level, message);
    logger->count++;

    /* 100行ごとにフラッシュ */
    if (logger->count % 100 == 0) {
        gzflush(logger->file, Z_SYNC_FLUSH);
    }
}

void logger_close(Logger *logger)
{
    if (logger) {
        gzclose(logger->file);
        free(logger);
    }
}

int main(void)
{
    Logger *log = logger_open("app.log.gz");
    if (!log) {
        fprintf(stderr, "ロガーの初期化に失敗\n");
        return 1;
    }

    logger_write(log, "INFO", "アプリケーション開始");
    logger_write(log, "DEBUG", "設定ファイルを読み込み中");
    logger_write(log, "INFO", "サーバーをポート 8080 で起動");
    logger_write(log, "WARNING", "メモリ使用率が 80%% を超えました");
    logger_write(log, "ERROR", "データベース接続がタイムアウトしました");
    logger_write(log, "INFO", "アプリケーション終了");

    logger_close(log);
    printf("ログの書き込みが完了しました\n");
    return 0;
}

7. 高度な API

7.1 はじめに

これまでの章で基本的な圧縮・展開の方法を学びました。この章では、zlib が提供する高度な機能――ストリームの状態管理、コピー、インクリメンタル処理、そして大きなファイルのサポートなど――について詳しく解説します。

7.2 deflate / inflate の状態管理

7.2.1 deflateReset() / inflateReset()

ストリームの内部状態をリセットし、同じ設定で新しいデータの処理を開始します。deflateEnd() + deflateInit() よりも効率的です。

z_stream strm;
memset(&strm, 0, sizeof(strm));
deflateInit(&strm, Z_DEFAULT_COMPRESSION);

/* 最初のデータを圧縮 */
/* ... deflate() でデータを処理 ... */

/* リセットして次のデータを圧縮 */
deflateReset(&strm);

/* 2番目のデータを圧縮（メモリの再確保なし） */
/* ... deflate() でデータを処理 ... */

deflateEnd(&strm);

Tip

同じ設定で繰り返し圧縮する場合（HTTP レスポンスの圧縮など）、deflateReset() を使うことでメモリ確保のオーバーヘッドを削減できます。

7.2.2 inflateReset2()

inflateReset() の拡張版で、windowBits を変更してリセットできます。

/* zlib 形式で開始 */
inflateInit2(&strm, 15);

/* ... 処理 ... */

/* gzip 形式に切り替えてリセット */
inflateReset2(&strm, 15 + 16);

7.3 ストリームのコピー

7.3.1 deflateCopy()

圧縮ストリームの完全なコピーを作成します。

int deflateCopy(z_streamp dest, z_streamp source);

同じデータに対して異なる圧縮オプションを試したい場合や、チェックポイントを作成したい場合に有用です。

z_stream strm1, strm2;
memset(&strm1, 0, sizeof(strm1));
deflateInit(&strm1, Z_DEFAULT_COMPRESSION);

/* 共通ヘッダ部分を圧縮 */
strm1.next_in = header_data;
strm1.avail_in = header_len;
strm1.next_out = out_buf;
strm1.avail_out = out_size;
deflate(&strm1, Z_NO_FLUSH);

/* ここでストリームをコピー */
deflateCopy(&strm2, &strm1);

/* strm1 でデータ A を圧縮 */
strm1.next_in = data_a;
strm1.avail_in = data_a_len;
deflate(&strm1, Z_FINISH);
deflateEnd(&strm1);

/* strm2 でデータ B を圧縮（ヘッダ部分は再計算不要） */
strm2.next_in = data_b;
strm2.avail_in = data_b_len;
deflate(&strm2, Z_FINISH);
deflateEnd(&strm2);

7.4 deflateParams() — パラメータの動的変更

圧縮の途中で、圧縮レベルや戦略を変更できます。

int deflateParams(z_streamp strm, int level, int strategy);

z_stream strm;
memset(&strm, 0, sizeof(strm));
deflateInit(&strm, Z_DEFAULT_COMPRESSION);

/* テキストデータの圧縮（デフォルト戦略） */
strm.next_in = text_data;
strm.avail_in = text_len;
/* ... deflate() ... */

/* バイナリデータに切り替え（圧縮レベルを上げる） */
deflateParams(&strm, Z_BEST_COMPRESSION, Z_DEFAULT_STRATEGY);

strm.next_in = binary_data;
strm.avail_in = binary_len;
/* ... deflate() ... */

8. Deflate アルゴリズムの詳細

8.1 はじめに

第3章では Deflate アルゴリズムの概要を紹介しました。この章では、そのアルゴリズムの内部構造をさらに深く掘り下げます。Deflate がどのようにデータを圧縮しているのかを理解することで、圧縮パラメータの選択やパフォーマンスチューニングに役立てることができます。

8.3 LZ77 の詳細

8.3.1 スライディングウィンドウ

LZ77 は「スライディングウィンドウ」と呼ばれる固定サイズの参照バッファを使います。zlib のデフォルトでは 32KB（windowBits=15, 2^15=32768）のウィンドウを使用します。

現在の位置から先読みバッファのデータを、ウィンドウ内のデータと照合します。一致する部分列が見つかれば、(距離, 長さ) のペアで表現します。

8.3.2 一致の検索

zlib はハッシュチェーンを使って効率的に一致を検索します。

  1. 先頭3バイトからハッシュ値を計算
  2. ハッシュテーブルで同じハッシュ値の位置を検索
  3. 実際にデータを比較して一致長を確認
  4. ハッシュチェーンをたどって、より長い一致を探索

8.3.3 遅延評価（lazy matching）

zlib は「遅延評価」という最適化手法を使います。現在の位置で一致が見つかっても、次の位置でより長い一致が見つかるかもしれません。

位置 100: "ABCDE..." → ウィンドウ内で 4バイトの一致を発見
位置 101: "BCDEF..." → ウィンドウ内で 7バイトの一致を発見  ★こちらを採用

この場合、位置 100 の文字をリテラルとして出力し、位置 101 からの7バイトの一致を使います。

圧縮レベルが低い場合はこの遅延評価が省略され、速度が向上します。

8.3.4 リテラルと長さ・距離のペア

LZ77 の出力は、2種類のシンボルで構成されます。

  1. リテラル: 一致が見つからなかった場合の生のバイト（0〜255）
  2. 長さ・距離ペア: 一致が見つかった場合の参照
    • 長さ: 3〜258 バイト
    • 距離: 1〜32768 バイト

8.4 ハフマン符号化の詳細

8.4.1 固定ハフマンテーブル

Deflate の固定ハフマンテーブルは、RFC 1951 で定義されています。

リテラル/長さ値 ビット数 コード範囲
0〜143 8 00110000〜10111111
144〜255 9 110010000〜111111111
256（ブロック終端） 7 0000000
257〜279 7 0000001〜0010111
280〜287 8 11000000〜11000111

固定テーブルはデータに関係なく常に同じなので、テーブル自体を保存する必要がありません。小さなデータブロックでは、動的テーブルよりも効率的です。

8.4.2 動的ハフマンテーブル

動的ハフマンテーブルは、実際のデータの出現頻度に基づいて構築されます。テーブル自体もブロック内に符号化して保存する必要がありますが、データに最適化されているため、十分なサイズのブロックでは固定テーブルよりも高い圧縮率が得られます。

テーブルのコンパクトな表現のために、3段階のエンコーディングが行われます。

  1. 各シンボルのコード長（ビット数）を列挙
  2. コード長の列をランレングス符号化（繰り返しの圧縮）
  3. ランレングスシンボル自体をハフマン符号化

8.4.3 ハフマンツリーの制約

Deflate のハフマンツリーにはいくつかの制約があります。

  • リテラル/長さのコード長は最大 15 ビット
  • 距離のコード長は最大 15 ビット
  • コード長のコード長は最大 7 ビット

8.6 圧縮戦略の内部動作

8.6.1 Z_DEFAULT_STRATEGY

通常の LZ77 + ハフマン符号化を実行します。一般的なデータに最適です。

8.6.2 Z_FILTERED

ハッシュチェーンの探索を強化し、小さな一致よりもリテラルのハフマン符号化を重視します。フィルタ処理後のデータ（差分エンコーディングなど）に効果的です。

8.6.3 Z_HUFFMAN_ONLY

LZ77 の一致検索をまったく行わず、ハフマン符号化のみを行います。すでに LZ77 的な前処理が施されたデータに適しています。

8.6.4 Z_RLE

距離1（直前の文字との一致）のみを検索します。PNG 画像のフィルタ後のデータのように、隣接するバイト間に強い相関があるデータに最適です。

8.6.5 Z_FIXED

動的ハフマンテーブルを使わず、常に固定テーブルを使用します。非常に小さなデータブロックで有効ですが、通常は zlib が自動的に最適なテーブルを選択します。

zlib は入力データを複数のブロックに分割します。ブロック分割の方針は以下のとおりです。

  • Z_SYNC_FLUSH や Z_FULL_FLUSH でも強制的にブロックが閉じられる

typedef struct {
    size_t total_allocated;
    size_t current_allocated;
    size_t peak_allocated;
    int allocation_count;
} MemoryTracker;

void *tracking_alloc(void *opaque, unsigned items, unsigned size)
{
    MemoryTracker *tracker = (MemoryTracker *)opaque;
    size_t total = (size_t)items * size;

    /* メタデータ用の追加領域を確保 */
    size_t *ptr = (size_t *)malloc(total + sizeof(size_t));
    if (!ptr) return NULL;

    /* サイズを先頭に記録 */
    *ptr = total;

    tracker->total_allocated += total;
    tracker->current_allocated += total;
    tracker->allocation_count++;

    if (tracker->current_allocated > tracker->peak_allocated) {
        tracker->peak_allocated = tracker->current_allocated;
    }

    return ptr + 1;
}

void tracking_free(void *opaque, void *address)
{
    if (!address) return;
    MemoryTracker *tracker = (MemoryTracker *)opaque;

    size_t *ptr = (size_t *)address - 1;
    tracker->current_allocated -= *ptr;

    free(ptr);
}

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <zlib.h>

double benchmark_compress(const Bytef *data, uLong data_len,
                          int level, int chunk_size)
{
    z_stream strm;
    memset(&strm, 0, sizeof(strm));
    deflateInit(&strm, level);

    uLong out_size = deflateBound(&strm, data_len);
    Bytef *output = (Bytef *)malloc(out_size);
    Bytef *chunk_buf = (Bytef *)malloc(chunk_size);

    clock_t start = clock();
    const int iterations = 100;

    for (int iter = 0; iter < iterations; iter++) {
        deflateReset(&strm);
        uLong offset = 0;
        uLong out_offset = 0;

        while (offset < data_len) {
            uLong remaining = data_len - offset;
            uLong this_chunk = remaining < (uLong)chunk_size
                               ? remaining : (uLong)chunk_size;

            strm.next_in = (Bytef *)(data + offset);
            strm.avail_in = (uInt)this_chunk;
            int flush = (offset + this_chunk >= data_len)
                        ? Z_FINISH : Z_NO_FLUSH;

            do {
                strm.next_out = chunk_buf;
                strm.avail_out = chunk_size;
                deflate(&strm, flush);
                out_offset += chunk_size - strm.avail_out;
            } while (strm.avail_out == 0);

            offset += this_chunk;
        }
    }

    clock_t end = clock();
    double elapsed = (double)(end - start) / CLOCKS_PER_SEC;

    deflateEnd(&strm);
    free(output);
    free(chunk_buf);

    return elapsed / iterations;  /* 1回あたりの時間 */
}

{

9.5 ストリームの再利用

HTTP サーバーのように、同じ種類のデータを繰り返し圧縮する場合、ストリームを再利用することで初期化コストを削減できます。

/* HTTP レスポンスの圧縮例 */
typedef struct {
    z_stream strm;
    Bytef *out_buf;
    uInt out_buf_size;
    int initialized;
} Compressor;

int compressor_init(Compressor *c, int level, uInt buf_size)
{
    memset(&c->strm, 0, sizeof(c->strm));
    c->out_buf_size = buf_size;
    c->out_buf = (Bytef *)malloc(buf_size);
    if (!c->out_buf) return Z_MEM_ERROR;

    int ret = deflateInit2(&c->strm, level, Z_DEFLATED,
                           15 + 16, 8, Z_DEFAULT_STRATEGY);
    c->initialized = (ret == Z_OK);
    return ret;
}

/* 各リクエストの処理 */
int compressor_compress(Compressor *c, const Bytef *input, uLong input_len,
                        Bytef **output, uLong *output_len)
{
    /* ストリームをリセット（再初期化より高速） */
    deflateReset(&c->strm);

    uLong max_out = deflateBound(&c->strm, input_len);
    Bytef *result = (Bytef *)malloc(max_out);
    if (!result) return Z_MEM_ERROR;

    c->strm.next_in = (Bytef *)input;
    c->strm.avail_in = (uInt)input_len;
    c->strm.next_out = result;
    c->strm.avail_out = (uInt)max_out;

    int ret = deflate(&c->strm, Z_FINISH);
    if (ret != Z_STREAM_END) {
        free(result);
        return Z_BUF_ERROR;
    }

    *output = result;
    *output_len = c->strm.total_out;
    return Z_OK;
}

void compressor_destroy(Compressor *c)
{
    if (c->initialized) {
        deflateEnd(&c->strm);
    }
    free(c->out_buf);
}

9.6 パフォーマンスのヒント

9.6.1 圧縮

  1. 適切な圧縮レベル: レベル 1 と 6 では速度が大きく異なるが、6 と 9 では圧縮率の差がわずか
  2. 大きな windowBits: メモリが許す限り大きく（最大15）。圧縮率が向上する
  3. 適切な memLevel: 通常は 8（デフォルト）で十分
  4. ストリームの再利用: deflateReset() は deflateEnd() + deflateInit() より高速
  5. バッチ処理: 小さなデータの個別圧縮よりも、まとめて圧縮する方が効率的

9.6.2 展開

  1. 十分な出力バッファ: 出力バッファが小さいと inflate() の呼び出し回数が増加
  2. inflateInit2() の自動検出: windowBits + 32 で zlib/gzip を自動判別すれば、形式を事前に調べる必要がない
  3. 展開は圧縮より高速: 展開処理は一般的に圧縮の2〜4倍高速

9.6.3 一般的な注意点

  • アラインメント: 入出力バッファは自然なアラインメント境界に配置する
  • キャッシュ効率: チャンクサイズを L2 キャッシュサイズ以下に抑える
  • 並列処理: 独立したデータは別スレッドで並行圧縮可能（各スレッドに独自の z_stream を使用）

Important

zlib の z_stream はスレッドセーフではありません。複数のスレッドから同じ z_stream にアクセスする場合は、適切な排他制御が必要です。ただし、異なる z_stream を異なるスレッドで使用することは安全です。

9.6.4 マルチスレッド利用時の注意

zlib をマルチスレッド環境で使用する際は、以下の点に注意が必要です。

z_stream の同時アクセス禁止

z_stream 構造体は内部状態を持つため、同じインスタンスに複数のスレッドから同時にアクセスしてはいけません。deflate() や inflate() は呼び出しのたびに内部状態を更新するため、排他制御なしに同時呼び出しするとデータ破壊やクラッシュの原因になります。

/* 悪い例: 複数スレッドで同じ z_stream を共有 */
z_stream shared_strm;  /* グローバルまたは共有 */

void *thread_func(void *arg)
{
    /* 危険: 他のスレッドと同時に shared_strm を操作する可能性がある */
    shared_strm.next_in = input;
    shared_strm.avail_in = input_len;
    deflate(&shared_strm, Z_NO_FLUSH);  /* データ破壊・クラッシュの恐れ */
    return NULL;
}

/* 良い例: スレッドごとに独立した z_stream を使用 */
void *thread_func(void *arg)
{
    z_stream strm;
    memset(&strm, 0, sizeof(strm));
    deflateInit(&strm, Z_DEFAULT_COMPRESSION);

    strm.next_in = input;
    strm.avail_in = input_len;
    deflate(&strm, Z_FINISH);

    deflateEnd(&strm);
    return NULL;
}

共有が必要な場合の排他制御

やむを得ず z_stream を共有する場合は、mutex 等で排他制御を行います。ただし、ロック競合によりマルチスレッドの性能メリットが失われるため、通常はスレッドごとに独立した z_stream を用意する方が望ましいです。

pthread_mutex_t strm_mutex = PTHREAD_MUTEX_INITIALIZER;
z_stream shared_strm;

void compress_chunk(unsigned char *in, size_t in_len,
                    unsigned char *out, size_t *out_len)
{
    pthread_mutex_lock(&strm_mutex);

    shared_strm.next_in = in;
    shared_strm.avail_in = in_len;
    shared_strm.next_out = out;
    shared_strm.avail_out = *out_len;
    deflate(&shared_strm, Z_NO_FLUSH);
    *out_len = *out_len - shared_strm.avail_out;

    pthread_mutex_unlock(&strm_mutex);
}

グローバル関数のスレッドセーフ性

zlibVersion() や compressBound() など、z_stream を受け取らないユーティリティ関数は内部状態を変更しないため、複数スレッドから同時に呼び出しても安全です。

一方、compress() / uncompress() は内部で一時的な z_stream を作成・破棄するため、関数自体はスレッドセーフです。ただし、渡すバッファが他のスレッドと共有されていないことを確認してください。

カスタムメモリアロケータの注意

deflateInit2() 等で zalloc / zfree にカスタムアロケータを設定する場合、そのアロケータ自体がスレッドセーフである必要があります。標準の malloc() / free() は通常スレッドセーフですが、独自のメモリプールを使う場合は注意が必要です。

10.3 各エラーの詳細

10.3.1 Z_STREAM_ERROR (-2)

原因: ストリームの状態が不正、またはパラメータが無効。

/* よくある原因 1: 初期化前にストリームを使用 */
z_stream strm;
/* memset なし、初期化なし */
deflate(&strm, Z_NO_FLUSH);  /* → Z_STREAM_ERROR */

/* よくある原因 2: 無効なパラメータ */
deflateInit(&strm, 42);  /* レベル 42 は不正 → Z_STREAM_ERROR */

/* よくある原因 3: deflateEnd 後に deflate を呼ぶ */
deflateEnd(&strm);
deflate(&strm, Z_NO_FLUSH);  /* → Z_STREAM_ERROR */

対策: ストリームの初期化を確実に行い、有効なパラメータを使用する。

10.3.2 Z_DATA_ERROR (-3)

原因: 入力データが壊れている、または期待する形式と異なる。

/* よくある原因 1: 圧縮されていないデータを展開しようとした */
const char *plain = "This is not compressed";
/* ... inflate() → Z_DATA_ERROR */

/* よくある原因 2: gzip データを zlib 形式として展開 */
inflateInit(&strm);  /* zlib 形式 */
/* gzip データを入力 → Z_DATA_ERROR */

対策: データ形式の確認、inflateInit2() で正しい形式を指定、または自動検出（windowBits + 32）を使用する。

10.3.3 Z_MEM_ERROR (-4)

原因: メモリの確保に失敗。

/* 対策: エラーチェックとリソースの解放 */
int ret = deflateInit(&strm, level);
if (ret == Z_MEM_ERROR) {
    fprintf(stderr, "メモリ不足: 圧縮を開始できません\n");
    /* 他のリソースを解放してから再試行を検討 */
}

対策: windowBits や memLevel を小さくしてメモリ使用量を減らす。

10.3.4 Z_BUF_ERROR (-5)

原因: 出力バッファが足りない、または入力データがない状態での処理。

/* 重要: Z_BUF_ERROR は致命的エラーではない場合が多い */
ret = inflate(&strm, Z_NO_FLUSH);
if (ret == Z_BUF_ERROR) {
    if (strm.avail_out == 0) {
        /* 出力バッファが一杯 → バッファを書き出して続行 */
    }
    if (strm.avail_in == 0) {
        /* 入力データを追加して続行 */
    }
}

Important

Z_BUF_ERROR は inflate() や deflate() で返されることがありますが、多くの場合は致命的なエラーではありません。バッファを補充して処理を再開できます。ただし、uncompress() が返す Z_BUF_ERROR は、出力バッファのサイズ不足を意味するため、バッファを大きくして再試行する必要があります。

10.3.5 Z_VERSION_ERROR (-6)

原因: zlib のヘッダファイル（zlib.h）とリンクされたライブラリのバージョンが互換性がない。

/* バージョンの確認 */
printf("ヘッダバージョン:     %s\n", ZLIB_VERSION);
printf("ライブラリバージョン: %s\n", zlibVersion());

/* バージョン不一致の検出 */
if (strcmp(ZLIB_VERSION, zlibVersion()) != 0) {
    fprintf(stderr, "警告: zlib のバージョンが一致しません\n");
}

対策: コンパイル環境とランタイム環境で同じバージョンの zlib を使用する。

z_stream の msg フィールドには、最後のエラーに関する説明文字列が設定されることがあります。

ZlibResult safe_compress(Bytef *dest, uLongf *dest_len,
                         const Bytef *source, uLong source_len,
                         int level)
{
    ZlibResult result = {0};

    /* パラメータ検証 */
    if (dest == NULL || dest_len == NULL || source == NULL) {
        result.code = Z_STREAM_ERROR;
        result.msg = "NULL ポインタが渡されました";
        return result;
    }

    if (level < -1 || level > 9) {
        result.code = Z_STREAM_ERROR;
        result.msg = "圧縮レベルは -1〜9 の範囲で指定してください";
        return result;
    }

    /* 出力バッファサイズの確認 */
    uLong required = compressBound(source_len);
    if (*dest_len < required) {
        result.code = Z_BUF_ERROR;
        result.msg = "出力バッファが小さすぎます";
        return result;
    }

    /* 圧縮実行 */
    result.code = compress2(dest, dest_len, source, source_len, level);
    result.input_bytes = source_len;
    result.output_bytes = *dest_len;

    switch (result.code) {
    case Z_OK:
        result.msg = "圧縮成功";
        break;
    case Z_MEM_ERROR:
        result.msg = "メモリ不足";
        break;
    case Z_BUF_ERROR:
        result.msg = "出力バッファが不足しています";
        break;
    case Z_STREAM_ERROR:
        result.msg = "無効なパラメータ";
        break;
    default:
        result.msg = "不明なエラー";
    }

    return result;
}

#include <stdlib.h>
#include <string.h>
#include <zlib.h>

typedef struct {
    unsigned char *data;
    size_t size;
} Buffer;

/*
 * HTTP レスポンスボディを gzip 圧縮する。
 * Accept-Encoding: gzip を確認した後に呼び出す想定。
 */
int gzip_compress_response(const char *body, size_t body_len,
                           Buffer *compressed)
{
    z_stream strm;
    memset(&strm, 0, sizeof(strm));

    /* gzip 形式で初期化 */
    int ret = deflateInit2(&strm, Z_DEFAULT_COMPRESSION, Z_DEFLATED,
                           15 + 16, 8, Z_DEFAULT_STRATEGY);
    if (ret != Z_OK) return ret;

    compressed->size = deflateBound(&strm, body_len);
    compressed->data = (unsigned char *)malloc(compressed->size);
    if (!compressed->data) {
        deflateEnd(&strm);
        return Z_MEM_ERROR;
    }

    strm.next_in = (Bytef *)body;
    strm.avail_in = (uInt)body_len;
    strm.next_out = compressed->data;
    strm.avail_out = (uInt)compressed->size;

    deflateEnd(&strm);

    if (ret != Z_STREAM_END) {
        free(compressed->data);
        compressed->data = NULL;
        return Z_BUF_ERROR;
    }

    compressed->size = strm.total_out;
    return Z_OK;
}

                           const void *data, size_t len,
                           int (*send_fn)(const void *, size_t, void *),
                           void *send_ctx)
{
    sc->strm.next_in = (Bytef *)data;
    sc->strm.avail_in = (uInt)len;

    do {
        sc->strm.next_out = sc->buf;
        sc->strm.avail_out = (uInt)sc->buf_size;

        int ret = deflate(&sc->strm, Z_SYNC_FLUSH);
        if (ret == Z_STREAM_ERROR) return ret;

        size_t have = sc->buf_size - sc->strm.avail_out;
        if (have > 0) {
            if (send_fn(sc->buf, have, send_ctx) != 0) {
                return Z_ERRNO;
            }
        }
    } while (sc->strm.avail_out == 0);

    return Z_OK;
}

int stream_compressor_finish(StreamCompressor *sc,
                             int (*send_fn)(const void *, size_t, void *),
                             void *send_ctx)
{
    sc->strm.avail_in = 0;
    sc->strm.next_in = Z_NULL;

    int ret;
    do {
        sc->strm.next_out = sc->buf;
        sc->strm.avail_out = (uInt)sc->buf_size;

        ret = deflate(&sc->strm, Z_FINISH);

        size_t have = sc->buf_size - sc->strm.avail_out;
        if (have > 0) {
            send_fn(sc->buf, have, send_ctx);
        }
    } while (ret != Z_STREAM_END);

    deflateEnd(&sc->strm);
    free(sc->buf);
    return Z_OK;
}

11.4 データベースのデータ圧縮

データベースに格納する BLOB データを圧縮する例です。

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <zlib.h>

/*
 * データベース格納用の圧縮データ形式:
 * [元のサイズ: 4バイト][圧縮データ]
 *
 * 元のサイズを先頭に付与することで、展開時のバッファ確保が容易になる。
 */

int db_compress(const void *src, size_t src_len,
                void **dst, size_t *dst_len)
{
    /* ヘッダ（4バイト: 元のサイズ）+ 圧縮データ */
    uLong compressed_bound = compressBound((uLong)src_len);
    *dst_len = 4 + compressed_bound;
    *dst = malloc(*dst_len);
    if (!*dst) return -1;

    /* 元のサイズをリトルエンディアンで記録 */
    unsigned char *p = (unsigned char *)*dst;
    p[0] = (src_len >>  0) & 0xFF;
    p[1] = (src_len >>  8) & 0xFF;
    p[2] = (src_len >> 16) & 0xFF;
    p[3] = (src_len >> 24) & 0xFF;

    /* 圧縮 */
    uLongf compressed_len = compressed_bound;
    int ret = compress2(p + 4, &compressed_len,
                        (const Bytef *)src, (uLong)src_len,
                        Z_DEFAULT_COMPRESSION);
    if (ret != Z_OK) {
        free(*dst);
        *dst = NULL;
        return ret;
    }

    *dst_len = 4 + compressed_len;
    return 0;
}

int db_decompress(const void *src, size_t src_len,
                  void **dst, size_t *dst_len)
{
    if (src_len < 4) return -1;

    /* 元のサイズを読み取り */
    const unsigned char *p = (const unsigned char *)src;
    *dst_len = (size_t)p[0]
             | ((size_t)p[1] <<  8)
             | ((size_t)p[2] << 16)
             | ((size_t)p[3] << 24);

    *dst = malloc(*dst_len);
    if (!*dst) return Z_MEM_ERROR;

    /* 展開 */
    uLongf decompressed_len = (uLongf)*dst_len;
    int ret = uncompress((Bytef *)*dst, &decompressed_len,
                         p + 4, (uLong)(src_len - 4));
    if (ret != Z_OK) {
        free(*dst);
        *dst = NULL;
        return ret;
    }

    *dst_len = decompressed_len;
    return 0;
}

11.6 インメモリ圧縮キャッシュ

メモリキャッシュに圧縮データを格納して、メモリ使用量を削減する例です。

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <zlib.h>

typedef struct CacheEntry {
    char *key;
    Bytef *compressed_data;
    uLong compressed_size;
    uLong original_size;
    struct CacheEntry *next;
} CacheEntry;

typedef struct {
    CacheEntry **buckets;
    size_t num_buckets;
    size_t count;
    size_t memory_saved;  /* 圧縮で節約できたバイト数 */
} CompressedCache;

CompressedCache *cache_create(size_t num_buckets)
{
    CompressedCache *cache = calloc(1, sizeof(CompressedCache));
    if (!cache) return NULL;
    cache->buckets = calloc(num_buckets, sizeof(CacheEntry *));
    if (!cache->buckets) { free(cache); return NULL; }
    cache->num_buckets = num_buckets;
    return cache;
}

static unsigned long hash_key(const char *key, size_t num_buckets)
{
    unsigned long hash = 5381;
    while (*key) {
        hash = ((hash << 5) + hash) + (unsigned char)*key++;
    }
    return hash % num_buckets;
}

int cache_put(CompressedCache *cache, const char *key,
              const void *data, size_t data_len)
{
    unsigned long idx = hash_key(key, cache->num_buckets);

    CacheEntry *entry = calloc(1, sizeof(CacheEntry));
    if (!entry) return -1;

    entry->key = strdup(key);
    entry->original_size = (uLong)data_len;

    /* データを圧縮して格納 */
    entry->compressed_size = compressBound((uLong)data_len);
    entry->compressed_data = (Bytef *)malloc(entry->compressed_size);

    int ret = compress(entry->compressed_data, &entry->compressed_size,
                       (const Bytef *)data, (uLong)data_len);
    if (ret != Z_OK) {
        free(entry->key);
        free(entry->compressed_data);
        free(entry);
        return ret;
    }

    /* リストの先頭に追加 */
    entry->next = cache->buckets[idx];
    cache->buckets[idx] = entry;
    cache->count++;
    cache->memory_saved += data_len - entry->compressed_size;

    return 0;
}

int cache_get(CompressedCache *cache, const char *key,
              void **data, size_t *data_len)
{
    unsigned long idx = hash_key(key, cache->num_buckets);

    for (CacheEntry *e = cache->buckets[idx]; e; e = e->next) {
        if (strcmp(e->key, key) == 0) {
            *data_len = e->original_size;
            *data = malloc(e->original_size);
            if (!*data) return Z_MEM_ERROR;

            uLongf out_len = e->original_size;
            int ret = uncompress((Bytef *)*data, &out_len,
                                 e->compressed_data, e->compressed_size);
            if (ret != Z_OK) {
                free(*data);
                *data = NULL;
                return ret;
            }
            return 0;
        }
    }
    return -1;  /* キーが見つからない */
}

void cache_stats(CompressedCache *cache)
{
    printf("キャッシュ統計:\n");
    printf("  エントリ数:     %zu\n", cache->count);
    printf("  節約メモリ:     %zu バイト\n", cache->memory_saved);
}

#include <stdlib.h>
#include <string.h>
#include <zlib.h>

#define CHUNK 16384

/*
 * 簡易アーカイブ形式:
 * [ファイル数: 4バイト]
 * ファイルごと:
 *   [ファイル名長: 2バイト][ファイル名][データサイズ: 4バイト][データ]
 * 全体を gzip で圧縮
 */

int archive_files(const char *output_path,
                  const char **filenames, int file_count)
{
    gzFile gz = gzopen(output_path, "wb6");
    if (!gz) return -1;

    /* ファイル数を書き込み */
    unsigned char header[4];
    header[0] = (file_count >>  0) & 0xFF;
    header[1] = (file_count >>  8) & 0xFF;
    header[2] = (file_count >> 16) & 0xFF;
    header[3] = (file_count >> 24) & 0xFF;
    gzwrite(gz, header, 4);

    for (int i = 0; i < file_count; i++) {
        /* ファイル名の書き込み */
        unsigned short name_len = (unsigned short)strlen(filenames[i]);
        unsigned char name_header[2];
        name_header[0] = (name_len >> 0) & 0xFF;
        name_header[1] = (name_len >> 8) & 0xFF;
        gzwrite(gz, name_header, 2);
        gzwrite(gz, filenames[i], name_len);

        /* ファイルデータの読み込みと書き込み */
        FILE *fp = fopen(filenames[i], "rb");
        if (!fp) {
            fprintf(stderr, "警告: %s を開けません\n", filenames[i]);
            /* サイズ 0 として記録 */
            unsigned char zero[4] = {0};
            gzwrite(gz, zero, 4);
            continue;
        }

        /* ファイルサイズを取得 */
        fseek(fp, 0, SEEK_END);
        long file_size = ftell(fp);
        fseek(fp, 0, SEEK_SET);

        unsigned char size_buf[4];
        size_buf[0] = (file_size >>  0) & 0xFF;
        size_buf[1] = (file_size >>  8) & 0xFF;
        size_buf[2] = (file_size >> 16) & 0xFF;
        size_buf[3] = (file_size >> 24) & 0xFF;
        gzwrite(gz, size_buf, 4);

        /* データの書き込み */
        unsigned char buf[CHUNK];
        size_t n;
        while ((n = fread(buf, 1, CHUNK, fp)) > 0) {
            gzwrite(gz, buf, (unsigned)n);
        }

        fclose(fp);
        printf("  追加: %s (%ld バイト)\n", filenames[i], file_size);
    }

    gzclose(gz);
    return 0;
}

B. 用語集

B.1 A

B.1.1 Adler-32

Mark Adler が考案した高速なチェックサムアルゴリズム。zlib 形式のデータ完全性チェックに使用される。CRC-32 より高速だが、エラー検出能力はやや劣る。

B.2 C

B.2.1 CRC-32

Cyclic Redundancy Check の 32 ビット版。gzip 形式のデータ完全性チェックに使用される。多くのファイル形式やネットワークプロトコルで広く採用されている。

B.2.2 compressBound

指定されたサイズのデータを圧縮した場合の最大出力サイズを計算する zlib 関数。出力バッファの確保に使用する。

B.3 D

B.3.1 Deflate

Phil Katz が設計した可逆圧縮アルゴリズム。LZ77 とハフマン符号化を組み合わせている。RFC 1951 で規定。zlib、gzip、ZIP、PNG など多くの形式で使用される。

B.4 F

B.4.1 flush（フラッシュ）

圧縮ストリームにおいて、内部バッファのデータを強制的に出力すること。Z_NO_FLUSH、Z_SYNC_FLUSH、Z_FULL_FLUSH、Z_FINISH などのモードがある。

B.5 G

B.5.1 gzip

GNU zip の略。ファイル圧縮用の形式とプログラム。RFC 1952 で規定。内部で Deflate アルゴリズムを使用し、ファイル名やタイムスタンプなどのメタデータと CRC-32 チェックサムを含む。

B.6 H

B.6.1 ハフマン符号化（Huffman coding）

出現頻度に基づいて可変長のビット列を割り当てる符号化方式。頻出するシンボルには短いコードを、稀なシンボルには長いコードを割り当てることで、全体のデータサイズを削減する。

B.6.2 ハッシュチェーン（Hash chain）

zlib の LZ77 実装で使用される、一致候補を効率的に検索するためのデータ構造。3バイトの部分文字列をハッシュ化し、同じハッシュ値を持つ位置をチェーンで管理する。

B.7 I

B.7.1 inflate

zlib における展開（decompression）操作。inflate() 関数がストリーム展開を行う。

B.8 L

B.8.1 LZ77

Abraham Lempel と Jacob Ziv が 1977 年に発表した辞書ベースの圧縮アルゴリズム。スライディングウィンドウ内の過去のデータから一致するパターンを検索し、距離と長さのペアで参照する。

B.8.2 lazy matching（遅延評価）

zlib の圧縮最適化手法。現在の位置で一致が見つかっても、次の位置でより長い一致がないか確認する。より長い一致を優先することで圧縮率が向上する。

B.9 M

B.9.1 memLevel

zlib の圧縮パラメータ。内部のハッシュテーブルサイズを制御する（1〜9）。値が大きいほどメモリを多く使用するが、圧縮速度が向上する。デフォルトは 8。

B.10 R

B.10.1 raw deflate

ヘッダやトレーラを含まない、Deflate アルゴリズムの生の圧縮データ。ZIP ファイルや PNG 画像の内部で使用される。zlib では windowBits に負の値を指定して使用する。

B.11 S

B.11.1 スライディングウィンドウ（Sliding window）

LZ77 アルゴリズムで使用される、過去のデータを保持する固定サイズのバッファ。zlib のデフォルトでは 32KB（windowBits=15）。

B.11.2 ストリーム処理（Stream processing）

データを小さなチャンクに分けて順次処理する方式。大きなデータを少ないメモリで処理できる。zlib では z_stream 構造体を中心に実現されている。

B.12.1 windowBits

zlib のパラメータ。スライディングウィンドウのサイズ（2^windowBits バイト）とデータ形式を制御する。8〜15 で zlib 形式、-8〜-15 で raw deflate、16 を加えると gzip 形式、32 を加えると自動検出。

B.13 Z

B.13.1 z_stream

zlib のストリーム処理の中心となる構造体。入出力バッファのポインタ、利用可能なバイト数、処理済みの総バイト数、エラーメッセージなどを保持する。

B.13.2 zlib 形式

Deflate 圧縮データに 2 バイトのヘッダ（CMF + FLG）と 4 バイトの Adler-32 チェックサムを付加した形式。RFC 1950 で規定。compress() / uncompress() のデフォルト形式。

B.13.3 zlib ライセンス

zlib に適用されるオープンソースライセンス。商用利用を含めほぼ自由に使用可能。バイナリ配布時のライセンス表記義務がないことが特徴。
